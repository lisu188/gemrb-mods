# GemRB class-mod compatibility matrix

This matrix distinguishes supported installation targets from completed live-engine acceptance. Automated fixture coverage and real campaign acceptance are separate signals.

| Mod | Version | Tutu / Tutu_TotSC | BGEE | Classic Adventures | BGT | BG2EE | EET | Live acceptance status |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Cipher | 0.3.0 | Supported | Supported | Supported | Supported | Supported | Supported | Scripted; BGEE and BG2EE-family live run still required |
| Psion | 1.4.0 | Supported | Supported | Supported | Supported | Supported | Supported | Scripted; BGEE and BG2EE-family live run still required |
| Sorcerer/Monk | 2.0 | Supported | Supported | Supported | Supported | Supported | Supported | Scripted; BGEE, BG2EE, and ToB/high-level live matrix still required |

Original BG1/TotSC is not a supported target for these custom classes because the required later class infrastructure is absent or incomplete.

## Cross-mod installation

Cipher and Psion share `GemRBModCore` but retain independent handler ownership. They can be installed in either order. Removing one handler leaves the shared runtime active while the other remains installed; removing the final handler restores the original GemRB GUI files and shared modules.

Sorcerer/Monk does not install a shared GUI handler and can coexist with Cipher/Psion when the target class tables have enough valid sub-32 class-ID capacity. Its legacy Sorcerer/Monk/Cleric predecessor remains mutually exclusive with Sorcerer/Monk.

## Recommended install path

Use the repository/release driver so matching shared files are staged together:

```bash
python tools/gemrb_mods.py install cipher psion sorcerer-monk \
  --game /path/to/game \
  --guiscripts /path/to/GemRB/gemrb/GUIScripts \
  --weidu /path/to/weidu
```

For Cipher/Psion, `--guiscripts` is mandatory. For Sorcerer/Monk alone it is unnecessary.

Release ZIPs generated by `tools/gemrb_mods.py package` contain a SHA-256 manifest. A mismatched packaged file is rejected before game or GemRB mutation.

## Validation terminology

- **Supported** means the installer/runtime code intentionally handles that target and automated source/fixture tests cover its relevant table family.
- **Automated validated** means CI has exercised parser/runtime/fixture contracts without proprietary game assets.
- **Live accepted** means an operator has run the documented scenario on real game data under GemRB and recorded the result and GemRB revision.

The repository does not infer live acceptance from automated fixture success.
